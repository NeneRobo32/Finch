## 一、总体判断

**这套 UI 已经不是「设计不到位」的问题，而是「三个界面的承诺比实现走得快」：视觉语言立得住、信息架构在 v0.29 真的变好了、令牌化做到 82%（个人项目里的上游水平）——但它承诺了三件自己做不到的事。**

1. **它承诺「愿望单会提醒你降价」**，实际只在发售日推一条通知（`ReleaseCheckWorker.kt:51-52` 只判 `days`）。愿望单目前是书签。
2. **它承诺「这是 PSN 港服的现价」**，实际离线时会静默回退到几周前的快照，界面上没有任何时间戳（`UpcomingViewModel.kt:243-258`）。
3. **它承诺「我的筛选/搜索/翻到的月份还在」**，实际切个 tab 就全丢（`FinchAppScaffold.kt:115-144`，全仓库 `SaveableStateHolder` 0 命中）。

**一句话结论：先修「说错话」的三处，再修「看不清」的四处，最后才动审美。** 现在直接做视觉升级，会把三处信任问题埋在更漂亮的外壳下面。

一份可以贴在墙上的成熟度评分（10 分制，三路各自打分后取中位）：

| 维度 | 分 | 一句话依据 |
|---|---|---|
| 视觉语言一致性 | 7.0 | 有辨识度，但同一套语言被局部改写了 6 次（hero 4 种实现、5~7 种蓝、圆角实际 9 档） |
| 信息架构 | 7.5 | v0.29 修掉了密度与分组，但「日程」一页塞三种意图，且 tab 名覆盖不了 |
| 无障碍 | 5.5 | 命中区已达标；对比度 4 处不合格（最低 1.80:1），底栏缺 `selected` 语义 |
| 绘制/性能 | 5.0 | 玻璃链路 3 处结构性浪费（一处是每帧白烧的模糊） |
| 令牌化 | 8.2 | 82% 覆盖；缺口不在「还有字面量」，在**令牌只覆盖了值、没覆盖组合**（见 §3.3） |
| 可测试性 | 2.0 | 0 个 `@Preview`、0 个 `androidTest`、0 个 `testTag` |

## 二、三路交叉：同一个病，三种说法

这是汇编的真正价值——三份报告独立跑出来，有 6 组问题其实指向同一个根因，而且**其中两组的改法互相冲突，必须由人拍板**。

### 2.1 六组交叉印证（改一处，三处受益）

| # | 现象 | 视觉侧说法 | 体验侧说法 | 实现侧说法 | 真实根因 |
|---|---|---|---|---|---|
| X1 | 切 tab 回来啥都没了 | — | P0-4 整页状态归零 | A5 `AnimatedContent` 无 `SaveableStateHolder` | 缺一个 20 行的 `SaveableStateHolder` |
| X2 | 有些字看不清 | V1 奖牌白字 1.80:1 / V2 悬浮顶栏 2.0:1 / V10 红底 3.91:1 | P1-3 选中态白字 3.7:1 | — | **4 处同一个错**：白字压在中亮底上，没算对比度 |
| X3 | 大字号下界面崩 | V11 价格缩到 13sp 比标题还小 | P1-4 分段/按钮文字被裁；P1-5 标题被挤成两字 | C5 `autoSize` 在 2.0x 下反向缩小 | **用定高 + 硬拟合顶大字号**，而不是让布局自适应 |

| X5 | 玻璃又贵又薄 | V3 缺中景：背景满饱和 + 卡片零色相 | — | A1 每行白导一层 / A2 阴影被自己裁掉 / A3 弹层跨窗口采样 | 材质系统**同时**在性能上浪费、在层级上缺席 |
| X6 | 同一屏好几个蓝 | V6 渐变搭档 0.3/0.4/0.45 三处散写 | P2-2 设置与筛选用同一个 `Tune` 图标 | `FinchMotion` 缺 fade 档 → 转场 100% 字面量 | **令牌只覆盖单值，没覆盖「组合」** |

### 2.2 两处冲突，需要你拍板

**冲突一：修性能会让界面变「实」。**
impl 的 A3（弹层里 `LocalGlassEnabled provides false`）会让所有 `FinchSheet` 内的 chip 和确认按钮从玻璃退化为实色；A1（`Card`→`Tile`）会让主页列表卡薄一档。这两条在性能上是纯赚，在观感上是减法。visual 的 §6「明确不动」清单里，弹层玻璃没被列入冻结区，所以他倾向可接受，但要求先看一眼。
→ **我的建议：先改，真机对比再决定是否回退**。因为 A3 同时消除了 32 个 chip 的跨窗口采样（这是弹层打开时掉帧的主因），收益是「不卡」而不是「省电」，属于体验底线。

**冲突二：visual 的方向 A（给卡片补中性底）与 impl 的 A1（Card→Tile 变薄）方向相反。**
方向 A 要 `Card.tintScale 0.22→0.38`（更实、更不透），A1 要把列表行从 Card 降到 Tile（更薄、更透）。两者叠加的净效果不确定。
→ **我的裁决：先做 A1（一致性 + 性能，零设计决策），方向 A 单独做视觉评审**。不要在同一次改动里既降档又加厚——那会让「到底哪个改动导致观感变了」无法归因。

## 三、优先级收敛：5 个 P0 组

三份报告各自标了 12 条 P0（视觉 3 + 体验 4 + 实现 5）。合并去重后，**真正该在今天决定的只有 5 组**：

### P0-A ｜「价格是哪天的价」——数据可信度（合并 ux P0-2 + P0-3）
- 缓存回退无时间戳（`UpcomingViewModel.kt:243-258` 只有一行 `Log.w`）；页头副标题恒为「三源聚合」（`UpcomingScreen.kt:117`）。
- 更严重的一层：`catch` 把异常吞成 `emptyList()`（`:190-193`），随后 `r.isEmpty()` 统一判 `Failed`（`:198-209`）——**`friendMsg(e)` 里写好的超时/SSL/地区限制文案永远到不了界面**，用户只看到「没有返回数据（网络或源问题）」，还会顶掉上一屏已有内容。
- **验收标准**：离线时页面必须出现「离线 · 数据为 11月2日 21:30 的快照」；失败时必须保留旧列表 + 顶部错误条，并显示具体原因。

### P0-B ｜「为什么没提醒我」——愿望单闭环（ux P0-1）
- `ReleaseCheckWorker.kt:51-52` 唯一判据是 `days in 0..notifyDays`，价格变化永不触发；`syncFollowPrices`（`UpcomingViewModel.kt:264-290`）同步了价格却不比较、不通知。
- **这是产品承诺缺失，不是 UI 缺陷**。要么补通知（`ReleaseFollow` 加 `prevPriceText`/`lastNotifiedAt` + 新 channel），要么把入口文案从「降价会提醒你」改成「收藏到愿望单」——**不能继续挂着假承诺**。
- 顺带：取消关注单击即删、无确认无撤销（ux P1-8，`WishlistPane.kt:162`）。

### P0-C ｜「我翻到的月份呢」——状态可存活性（ux P0-4 = impl A5）
- `FinchAppScaffold.kt:115-144`。补 `rememberSaveableStateHolder()`；`StatsScreen.kt:105-106,155` 的 `mode`/`anchorMonth`/`weekStart` 由 `remember` 改 `rememberSaveable`（`YearMonth` 存 `toString()`）。
- 注意 impl 的补充：ViewModel 作用域是 Activity，**数据不丢，丢的纯是 UI 态**——所以这是 20~40 行的活，不是重构。

### P0-D ｜「这四个字看不见」——对比度（合并 ux P1-3 + V1/V2/V10）
| 位置 | 现状 | 改法 |
|---|---|---|
| 选中态实底 + 白字（Chip/Segmented/Button） | `#3D7FFF` + 白 = **3.70:1** | 新增单一 token `onPrimaryStrong`（visual 建议 `#2B63E0` 5.30:1 / ux 建议 `lerp(primary,Black,0.22)` ≈5.1:1）。**只建一个名字，别一个 PR 建两个** |
| 排行榜金/银/铜徽章 | 白字 **1.80 / 2.19 / 2.98:1** | 金属底保持明亮，**文字改深棕 `#241A05`**（9.6 / 7.9 / 5.8:1）。压深金属色会让「金」不像金 |
| 详情页悬浮顶栏 | 滚到浅色卡上时白图标 **≈2.0:1** | 随滚动切实底（`surface@0.92` + `onSurface` 图标）；最低成本是黑底 0.28→0.55 |
| 主页「计时中」红徽章 | `#E5484D` + 白 11sp = **3.91:1** | 统一走 `FinchBadge` 的 `error` 淡底 + 深字 |

### P0-E ｜「每张卡都在白烧一次模糊」——玻璃三处结构性浪费（impl A1/A2/A3）
- **A2 最刺眼**：`Glass.kt:203` 的 `.clip(shape)` 排在 `.then(glassModifier)` 之前 → 18dp 阴影画在裁剪之后被自己裁掉，**但每帧的 `BlurMaskFilter` 照跑**。仓库里 `Containers.kt:391-392` 已经是正确顺序（shadow→clip），照抄即可。
- **A1**：`HomeCards.kt:228` 列表行用 `Card` 档，而 `Glass.kt:143-145` 的注释假设「Card 只用于大卡片」。该行内容全是 `Text`，**没有任何控件采样导出的层** → 每行白录一张离屏层。改 `Tile` 一词。
- **A3**：`FinchSheet`/`FinchDialog`（`Containers.kt:471`/`357`）未置空 `LocalFinchBackdrop`，弹层内 32 个 chip 跨窗口采样——与 `UI_DESIGN_GUIDE §3.1` 的明文禁令相反。
- **合计 3 个文件、约 15 行**，是整份审查里性价比最高的一处。

> 其余 19 条 P1 / 15 条 P2 见三份子报告，本文不重复列举。其中需要单独点名的两条：**`@Preview` = 0**（所有改动只能靠真机，这是改版慢的结构性原因）、**`finchClickable` 的无条件 `graphicsLayer`**（`Tokens.kt:101-104`，两行改动可在稳态省掉全部 RenderNode）。

## 五、可直接写进 `UI_DESIGN_GUIDE.md` 的条款

合并三份报告的规范建议，去重后 14 条**必须**、4 条**建议**。建议插入位置：§2.5 颜色后新增 §2.6 色彩层级 / §2.7 数字排版；§2.4 形状表补 §2.8 卡片档位；§六 组件速查加 `FinchNumber` 一行。

### 5.1 必须（违反即技术债）
1. **一个颜色一个职责**：`primary` 只做交互；`dataScale` 只表示数量大小；`PlatformPalette` 只做平台分类；`tertiary` 只表示「暂停」。四者不得互借（现状：`tertiary` 一人 5 职，`platformColor` 借用主题语义色，见 visual §1.2）。
2. **实底 + 白字必须先算对比度**，≥4.5:1（大字号 ≥3:1）。浅色主题的实底小控件用压深值，大面积渐变仍可用 `primary`。
3. **渐变搭档只有一个系数**：`accentGradientEnd = lerp(primary, tertiary, 0.34f)`，禁止在调用点写 0.3/0.4/0.45。
4. **金属色只允许一套 `MedalPalette(gold,silver,bronze,platinum)`**；星级金 `#F5B301` 并入同族。**金属底禁止白字**。
5. **数据色阶 = 同色相多亮阶**，禁止用 `tertiary`/`error` 编码数值大小（现状热力图第 5 档从蓝跳紫，读成两类数据）。
6. **所有数字走 `FinchNumber`**，带 `fontFeatureSettings = "tnum"`。理由：`Type.kt` 不打包字体，不声明则计时器/价格随 OEM 比例数字抖动（全项目 `tnum` 0 命中）。
7. **数字:单位 = 2.6:1**，单位降一档、基线对齐。同一数字列等宽右对齐。
8. **中文标题不用负字距**：`headlineMedium` 字距归零、行高 33→35。负字距只属于拉丁数字。
   > 更正一个常见误判：57/45/38sp 三档带 −2.1%~−2.8% 负字距，但**调用点全是数字**（`StatsCards.kt:126`、`HomeCards.kt:145`、`GameDetailCards.kt:179`），真正落在中文上的只有 −1.1%，肉眼无感。所以**不要盲目归零**，要拆样式。
9. **中文 ≥32sp 字重封顶 SemiBold**（Bold 在中文大字上会糊成块）。
10. **卡片只有三档，档位 = 玻璃 style + 圆角一一绑定**：行卡 `Card`+`card(24)` / 辅助卡 `Tile`+`tile(18)` / hero `Hero`+`hero(32)`。不得交叉。
11. **`SolidPanel`（关玻璃）的 alpha 必须与 glass 档对齐**：Card 0.46 / Tile 0.38 / Hero 0.30 / Chrome 0.60。现状 Card 0.58 对 glass 0.145 是**4 倍落差**，开关一按整个明度系统被换掉。
12. **`SolidPanel` 禁用 `surfaceContainer*`**（M3 基线默认值带紫调，与 `#F5F7FB` 不同色系，`Glass.kt:259/269` 是存量）。
13. **页头 action 一律 `ghost` 且 ≤2 个**；玻璃圆底只用于页头之外的独立操作（现状主页 2 ghost + 1 玻璃混排，日程 3 个全玻璃占 144dp）。
14. **离线/缓存回退必须显示数据时间**。价格类页面无时间戳 = 不可上架级缺陷。

### 5.2 建议
15. 新增颜色前先问「它是不是某个已有 token 的假名」——项目已有 3 处同语义两套色（金属、红、蓝）。
16. 删 `ScenePalette`（36 个色值 / 消费方 0）与 `displayLarge`/`headlineLarge`（0 调用档位，留着等下一次被误用来排中文大标题）。
17. `FinchHeader.subtitle` 加 `maxLines = 1`，且不复述下方控件已有的信息。
18. 往底栏加元素前先算账：64dp 的底栏是全 App 单位面积绘制成本最高的区域（3 条 `drawBackdrop` + 1 层录制 + shadow + innerShadow）。

## 六、需要真机才能定的三件事

1. **玻璃叠加后的真实对比度**：`onSurfaceVariant #4F5866` 在 `#F5F7FB` 上静态 6.7:1 达标，但玻璃会采样氛围光。最容易翻车的是 `FinchBadge`（0.14α 底 + 0.2α 描边）压在玻璃上——建议在「深色自定义背景 + 浅色主题」下用取色器实测。
2. **A2 改完是否有视觉变化**：若阴影出现了，说明原来确实是 bug；若零变化，说明 `drawBackdrop` 内部自己裁，那这层 `clip` 本来就该删。两种结果都算修好。
3. **数字是否真的抖**：V12 的 `tnum` 是按「OEM 字体可能用比例数字」推断的。在小米/OPPO/华为上看详情页计时器每秒跳是否横向抖——抖则必须加，不抖则该条降为防御性规范。
