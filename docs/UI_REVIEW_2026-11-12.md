## 一、结论速览

设计系统本身是合格的：间距/动效/圆角只有一份口径（`FinchSpace` / `FinchMotion` / `FinchShapes`），玻璃分了四档层级，空状态、错误态、加载态都有统一组件，价格用 `TextAutoSize` 兜底长字符串——这些都不用动。

问题集中在四类，共 14 项：

| 编号 | 类型 | 标题 | 影响 | 成本 |
|---|---|---|---|---|
| A1 | 可用性 | 系统字号放大后三处固定高度容器会截断文字 | 无障碍 / 大字体用户 | 低 |
| A2 | 可用性 | 小号主题色文字对比度不足（约 3.4:1） | 弱光/低视力阅读 | 低 |
| A3 | 可用性 | 多个点击热区只有 36~40dp | 单手操作误触 | 低 |
| B1 | 密度 | 主页首屏 480dp 被控件占据，列表只剩 1~2 张卡 | 主功能被推走 | 中 |
| B2 | 密度 | 日程页三段控件竖排，列表起点下移约 150dp | 同上 | 低 |
| B3 | 信息架构 | 日程分组「已发售 → 待发售」，与页面主题相反 | 首屏看到的是过期信息 | 低 |
| B4 | 信息架构 | 统计页期数导航四层冗余（分段+箭头+滑杆+提示） | 认知负担 | 低 |
| B5 | 信息架构 | 愿望单入口是列表第 0 项，滚动后消失 | 入口不可回头 | 极低 |
| B6 | 信息架构 | 主页搜索框只在游戏数 > 8 时出现 | 布局随数据突变、8 款以内无法搜索 | 极低 |
| C1 | 一致性 | 愿望单页标题比其它 tab 右移 44dp | 视觉网格断裂 | 低 |
| C2 | 一致性 | 只有主页支持下拉刷新 | 手势预期落空 | 低 |
| C3 | 一致性 | 首次加载整页空白转圈，无骨架 | 闪烁与跳动 | 中 |
| C4 | 一致性 | 底栏/FAB/Snackbar 偏移量是散落字面量（132/172/108/56） | 改底栏高度必踩坑 | 极低 |
| D1 | 打磨 | 分组标题层级偏弱，与正文几乎同级 | 扫读效率 | 极低 |
| D2 | 打磨 | 长按删除是主页唯一入口且无任何暗示 | 发现性 | 中 |

## 二、可用性问题（优先修）

### A1 — 固定高度容器在大字号下截断

**证据**

| 位置 | 代码 | 风险 |
|---|---|---|
| `ui/HomeCards.kt:76` | `.height(196.dp)` 内放 `displaySmall`(38sp) + `titleLarge`(20sp) + `labelMedium` + `labelSmall` | 1.3x 字号下 49sp 数字 + 26sp 标题 + 边距 ≈ 已顶满，>1.3x 直接裁掉 |
| `ui/StatsCards.kt:94` | `.height(188.dp)` 内放 `displayMedium`(45sp)，1.3x 后 58sp | 同上，且 `SpaceBetween` 会把上下两段压在一起 |
| `ui/UpcomingScreen.kt:412` | 右列 `widthIn(min = 92.dp, max = 108.dp)`，内含 40dp 星标 + 紧凑按钮 | 字号放大后按钮文字被挤压或折行，右列溢出卡片 |

全项目没有一处读取 `fontScale`（`LocalDensity` 只出现在 `Reveal.kt` 与 Liquid 组件里用于 px 换算），也就是说这三处完全依赖「用户不改字号」。

**建议**

```kotlin
// HomeCards.kt / StatsCards.kt：把定高换成最小高，高度由内容决定
.heightIn(min = 196.dp)   // 原 .height(196.dp)

// 内容列不要用 SpaceBetween 撑开，改为 fixed 间距 + weight 的 Spacer
Column(Modifier.fillMaxSize().padding(FinchSpace.xxl)) {
    Text(label, style = labelMedium, ...)
    Spacer(Modifier.weight(1f, fill = false))
    Text(total, style = displayMedium, maxLines = 1, autoSize = ...)
    ...
}
```

```kotlin
// UpcomingScreen.kt：右列在窄宽/大字号时允许换行到第二行
FlowRow(
    modifier = Modifier.widthIn(min = 92.dp),
    horizontalArrangement = Arrangement.spacedBy(FinchSpace.xs),
    verticalArrangement = Arrangement.spacedBy(FinchSpace.xs),
) { PriceColumn(...); FinchIconButton(...); action() }
```

`FinchStatTile` 已经用 `TextAutoSize` 做了自适应，是全项目唯一处理了字号的组件，可作参照。

### A2 — 小号主题色文字对比度不足

**证据**

浅色主题 `primary = #3D7FFF`（`theme/AppThemes.kt:123`），相对亮度 ≈ 0.234。压在 `surface #F5F7FB` 或浅玻璃上，对比度 **≈ 3.4~3.7:1**。

WCAG AA 要求：正文（<18.66sp 且非粗体）≥ 4.5:1。以下位置都是 11sp 的主题色文字，全部不达标：

- `FinchBadge`（`ui/design/Controls.kt:552`）：倒计时、折扣百分比、平台徽章、`已在库`——这是日程页出现频率最高的元素
- `HomeCards.kt:290-296`：「· 已通关」
- `HomeCards.kt:306-316`：7 天内玩过的「上次玩 · …」整行强调
- `WishlistPane.kt:229`：汇总里的「最大折扣」

深色主题 `primary = #8FB8FF` 在 `#101418` 上约 9:1，**没有问题**，只需要修浅色。

**建议**：新增一个「小字强调色」token，只在光模式压暗，视觉上仍是主题色：

```kotlin
// theme/AppThemes.kt 的 FinchColorScheme 里加一个便捷属性
val accentText: Color
    get() = if (isDark) scheme.primary else lerp(scheme.primary, scheme.onSurface, 0.28f)

// FinchBadge 与所有 11sp 的强调文字改用 finchBundle().accentText
```

`lerp(#3D7FFF, #16181D, 0.28)` ≈ `#31416E`，对比度约 8:1；徽章底色 `primary.copy(alpha=0.14f)` 可保持不变，观感几乎不动。

### A3 — 点击热区低于 48dp

**证据**

| 组件 | 实际命中尺寸 | 说明 |
|---|---|---|
| `FinchIconButton`（`Controls.kt:257`，非 ghost 分支） | 40×40dp | `GlassSurface` + `finchClickable`，没有最小触控扩展 |
| `FinchChip`（`Controls.kt:307/316`） | 高约 36dp | `labelLarge`(20sp 行高) + 上下 8dp |
| `WishlistBar`（`UpcomingScreen.kt:280`） | 高约 36dp | `bodyMedium` + 上下 8dp |
| `FinchStars`（`Controls.kt:595`） | 38×38dp（`starSize+8`） | 30dp 星 + 4dp 边 |

Material 3 的默认 `IconButton` 内部会套 `minimumInteractiveComponentSize()`（48dp），但 `ghost` 分支设置了 `.size(40.dp)` 仍能拿到扩展命中区；而自绘的 `GlassSurface` 分支不会。

**建议**：不改视觉尺寸，只加命中扩展：

```kotlin
Box(
    Modifier
        .minimumInteractiveComponentSize()   // 只扩命中区，不扩绘制
        .size(40.dp)
        .clip(FinchShapes.pill)
        ...
)
```

Chip 与 WishlistBar 建议把垂直 padding 从 8dp 提到 10~12dp（高度 40~44dp），或在外面包 `minimumInteractiveComponentSize()`。

## 三、密度与信息架构

### B1 — 主页首屏被控件吃掉（建议优先做）

`HomeScreen` 首屏纵向预算（1080×2400 机型，可用高度约 700dp）：

| 元素 | 高度 |
|---|---|
| 页头（27sp 标题 + 11sp 副标题） | ≈ 58dp |
| 本月 hero | 196dp |
| 「我的游戏 · N」+ 排序按钮 | ≈ 40dp |
| 平台分段 | 46dp |
| 状态 chips（FlowRow，7 个约 2~3 行） | ≈ 80~120dp |
| 搜索框（>8 款时出现） | 56dp |
| 间距 | ≈ 60dp |
| **合计** | **≈ 540~580dp** |

留给列表只剩 1~2 张卡，而「看游戏库」才是这个页面的主任务。

**建议（两档，按投入选）**

- **B1-a 推荐**：筛选收成一行 —— 平台分段 + 右侧一个「筛选」图标（`Icons.Filled.Tune`，选中态用 `FinchBadge` 显示已启用条件数），点开 `FinchSheet` 放状态 chips + 收藏；搜索改成页头右侧图标，点开才展开 `FinchTextField`。首屏省下约 180dp。
- **B1-b 省事**：hero 196 → 156dp；状态 chips 默认只显示一行（`maxLines` 效果靠 `FlowRow(maxLines = 1)` + 末尾「更多」），`B6` 一并修掉。

### B2 — 日程页三段控件竖排

`UpcomingScreen.kt:122-144`：数据源 chips（一行）+ 常驻搜索框（56dp）+ 愿望单入口条（列表第 0 项，≈ 44dp）+ 间距，列表起点比页头低约 150dp。

**建议**：搜索改为页头 icon 展开（与 B1 同一套交互）；愿望单入口上移到页头右侧（星标 + 关注数角标），列表里那一条删掉，同时解决 B5。

### B3 — 日程分组顺序与页面主题相反

`UpcomingScreen.kt:218-223`：

```kotlin
val groups = listOf(
    "recent" to "本年度已发售",   // ← 首屏第一组是过期信息
    "coming" to "本年度待发售",
    "deal"   to "正在打折",
    "later"  to "更远期",
)
```

页面叫「发售日程」，用户来这里是为了**接下来买什么 / 什么时候发售**。

**建议**：`待发售 → 正在打折 → 更远期 → 已发售（默认折叠，标题改成「N 款已发售 · 展开」）`。已发售用可折叠分组，避免历史条目把新内容顶下去。

### B4 — 统计页期数导航四层冗余

`StatsScreen.kt:211-273` 的期数控制卡里同时有：月/年分段、上一期/下一期箭头、`FinchSlider`、以及一句「拖动滑杆快速切换」。

滑杆覆盖 12 个月且没有刻度与刻度标签，拖到「几月」靠猜；箭头已经能满足前后翻，滑杆只在「跨很多期」时有用。

**建议**：删滑杆 + 提示文字（省 60dp 和一次 Liquid 采样开销）；需要远跳时点标题弹一个月份网格（`FinchSheet`）。卡片高度从约 200dp 降到约 120dp。

### B5 — 愿望单入口会滚走

`UpcomingScreen.kt:196-198`：入口条是 `LazyColumn` 的 `item(key = "wishlist_entry")`。只要用户向下滑过一次，就再也看不到入口，只能滑回顶部（或靠返回键，但那时人已经在日程列表里）。

**建议**：跟随 B2 一起挪到页头右侧。

### B6 — 搜索框按数量出现

`HomeScreen.kt:409`：

```kotlin
if (query.isNotBlank() || games.size > 8) { FinchTextField(...) }
```

游戏从 8 款变 9 款时整页布局突然多出 56dp，且 8 款以内的用户根本没搜索入口。

**建议**：搜索入口恒定存在于页头（icon 形态不占位），B1-a 一并解决。

## 四、一致性

### C1 — 愿望单页标题右移 44dp

`WishlistPane.kt:88-111` 把返回键放在标题左侧同一行：

```kotlin
Row {
    FinchIconButton(ArrowBack, ...)   // 40dp
    Spacer(Modifier.width(FinchSpace.xs))  // 4dp
    FinchHeader(title = "愿望单", ...)
}
```

标题因此从 18dp 网格线移到 62dp，与「游戏库 / 发售日程 / 记录 / 总结 / 设置」全部错位。副标题「PSN 港服价格 / 折扣 / 发售日」也与下方 `WishSummary` 的信息重复。

**建议**：返回键单独一行放在大标题上方（小号 `labelLarge` + 返回箭头，高 40dp），标题保持左对齐 18dp：

```kotlin
Row(Modifier.finchClickable(onBack).padding(vertical = 8.dp), verticalAlignment = CenterVertically) {
    Icon(Icons.AutoMirrored.Filled.ArrowBack, "返回日程", Modifier.size(18.dp))
    Spacer(Modifier.width(FinchSpace.xs))
    Text("日程", style = labelLarge, color = onSurfaceVariant)
}
FinchHeader(title = "愿望单", subtitle = null, actions = { 刷新 })
```

### C2 — 只有主页支持下拉刷新

`HomeScreen.kt:309` 有 `PullToRefreshBox`；日程页、愿望单、统计页都只有右上角刷新图标。同一 App 里手势预期不一致。

**建议**：日程页包一层 `PullToRefreshBox`（复用 `UpcomingViewModel.refresh()`，用一个 `refreshing` 状态驱动），图标保留作兜底。

### C3 — 加载态是整页空白转圈

`UpcomingScreen.kt:146-150`：`Loading` 时整个列表区被 `FinchLoading` 顶掉，首帧是空白 → 转圈 → 内容突然出现，三次布局跳变。日程页每次切数据源都会重走一遍。

**建议**：首次加载用骨架（3 张与 `StoreEntryCard` 同高 120dp 的 `GlassSurface` + 灰块），切源/刷新时保留旧列表 + 顶部细进度条（`FinchProgressBar` 高度 2dp）。

### C4 — 底部让位偏移量散落

`FinchSpace.bottomBarClearance = 132.dp` 已有 token，但：

- `HomeScreen.kt:238` Snackbar `padding(bottom = 172.dp)`
- `HomeScreen.kt:339` 列表底部 `bottomBarClearance + 56.dp`（FAB 占位）
- `HomeScreen.kt:474` FAB `padding(bottom = 108.dp)`

底栏一旦改高，这三处不会跟着动，但 132 会。

**建议**：`FinchSpace` 补 `fabClearance`、`snackbarClearance`、`fabOffset`，全部由 `bottomBarClearance` 派生：

```kotlin
val fabOffset = bottomBarClearance - 24.dp
val snackbarClearance = bottomBarClearance + 40.dp
```

## 五、打磨项

### D1 — 分组标题层级偏弱

`Containers.kt:180-205` 的 `FinchSectionTitle` 用 `titleSmall`(14sp) + `onSurfaceVariant`，右侧计数再降一档 alpha 0.8。在玻璃上这组文字与卡内正文几乎同级，「本年度待发售 / 正在打折」的分段感被削弱。

**建议**：标题改 `onSurface` + `SemiBold`（仍是 14sp，不加粗字号），计数改成 `FinchBadge`（小胶囊），分段一眼可见，视觉重量只增加一点点。

### D2 — 长按删除无提示

`HomeCards.kt:218` 的 `onLongClick = { confirmDelete = true }` 是主页删除游戏的唯一入口，卡片上没有任何暗示；右侧那个 34dp 的播放圆钮反而更像可点区域（实际整个卡片是一个点击域）。

**建议（三选一，推荐 ①）**

1. 卡片右侧圆钮换成 `FinchIconButton(MoreVert, ghost)` 打开 `FinchDropdownMenu`（详情 / 删除），长按保留；
2. 首次进入主页给一次性提示（`Snackbar`：「长按卡片可删除」）；
3. 详情页底部加「删除游戏」，主页长按仅作快捷方式。

### 其余可选项（收益小，看心情）

- `WishlistPane.kt:186` 的筛选名「待打折」语义模糊（实际是 `discountText == null`，含原价与未打折预售），建议改「未打折」。
- `FinchHeader` 副标题是 `labelSmall`(11sp)，在玻璃上偏小，可提到 `labelMedium`(12sp)；这会让 `HomeScreen` 页头 +4dp，与 B1 一起算进预算。
- 底栏 5 个 tab + 11sp 标签，在 360dp 窄屏上每格约 64dp，中文两字够用，不必改。

## 七、明确不动的部分

以下全部保持原样，本次任何改动都不得触碰：

- `ui/design/Glass.kt` 全文件：`GlassStyle` 四档参数、`drawBackdrop` 的 `vibrancy/blur/lens` 配方、`GLASS_CHROMATIC`、`MAX_GLASS_DEPTH`、`SolidPanel` 降级
- `ui/design/FinchBackdrop.kt` / `FinchAurora.kt`：氛围背景与粒子星空
- `FinchAppScaffold` 的三层 backdrop 组合（`backgroundBackdrop` / `contentBackdrop` / `glassBackdrop`）
- `FinchBottomBar` 的 Liquid 胶囊与选中滑块
- `FinchShapes` 的连续曲率半径档位
